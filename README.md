# dsh-sidechat

Codex 风格的 DSH 侧边聊天：从当前主会话分叉出一条独立支线，在右侧面板里追问，主线不被打断；有结论再一键带回主对话。

> 第一版目标：交互与 Codex 的 Side Chat 对齐——**继承上下文、独立运行、划选提问、结论回流、可提升为正式会话**。

## 功能

- **独立侧线程**：优先调用 `sessions.create` 新建**空会话**——没有继承日志，界面和存储都不会出现主对话内容；只有宿主缺 create 面时才退回 `sessions.fork`（此时才需要下面的边界闸门）。
- **旧 fork 路径的显示保护**：对历史/兜底 fork 的线程，侧聊界面不显示继承历史——
  切点取自 fork 写入的 `session/end-seed`（`inherited: true`）事件，等价于 Codex 侧聊「开一个空白的支线」；切点未确定前显示「正在分叉」占位，不会先闪出主对话内容。
- **原生聊天界面**：侧聊复用 DSH 自带对话组件，流式输出、工具调用、审批、附件、模型选择的行为与主对话一致。
- **划选提问**：选中主对话中的任意文字，点「在侧聊中提问」，选区会以 DSH **原生引用节点**写入侧聊输入框（显示为引用块/芯片，不显示 Markdown 源码）；
  也兼容 dsh-quote-cards 的「在侧聊中提问」交接——它传过来的 `> **引用 · 选中文字**` Markdown 草稿会被拆回引用段，同样走原生引用节点。
  - 侧聊里的 composer 不是当前会话，`sessions.scope()` 常常拿不到，所以解析顺序是「scope → binding.ctx」；
  - 原生节点确实不可用时，退回的是**可读文本**（`引用：` + 原文），不是 `> …` 源码；
  - 交接按内容哈希记账：重启/恢复不会重复插入，但同一面板里新的一次「在侧聊中提问」仍会写入。
- **多侧聊并存**：每个侧聊是独立标签，`keepMounted` 保证切换标签不打断后台运行。
- **Codex 式顶栏**：只有两个控件——左侧「当前侧聊标题 ▾」点开是这条主对话的侧聊清单（当前条目标「当前」，按最近使用排序），右侧「⋯」收纳全部动作（新侧聊 / 带回主对话 / 在会话中打开 / 回到主对话）。不再有一排按钮。
- **结论回流**：把侧聊最新一条回答追加到主对话输入框（主输入框不可用时退回剪贴板）。
- **提升为会话**：点「在会话中打开」，侧聊会话直接成为当前主会话，可继续长期使用。
- **列表不重复**：侧聊子会话被列表投影隐藏，不会在会话列表里冒出第二份对话；提升为正式会话时自动恢复显示。
- **模型跟随**：fork 只继承 agent preset，因此插件会把主会话的 provider/model/思考等级同步到侧聊（读取 `modelSelection` 投影，写入 `remote.session.selectModel`），侧聊内改模型不会回写主线。
- **自动命名**：标签标题取侧聊第一条提问的前 32 字，刷新后仍保留。
- **紧凑布局**：侧栏比主栏窄，插件通过宿主自己的 `--dsh-content-*` 变量收紧字号、内边距与输入框留白，不改宿主 DOM。
- **入口与恢复**：会话顶栏「侧聊」按钮——**第一次点开新侧聊；之后再点会先列出这个会话已有的侧聊让你挑一个继续**（也可选「+ 新侧聊」）。
- **清单可恢复**：侧聊清单只是投影，真正持久的记录是每个面板的 tab 记录（包含 child）。
  即使清单被旧版本清理过，打开面板或点顶栏「侧聊」时会从这些记录自动重建清单，不会丢历史侧聊。
- **只有真正的对话才算侧聊记录**：打开面板会先 fork 一个隐藏子会话供输入框使用，但它在你发出第一条消息之前不会登记成侧聊清单项；「+ 新侧聊」在空线程上不会重复 fork，历史遗留的空记录也会被自动清理。
  一个主会话始终只有一个侧聊面板，重复点击不会再多开标签、也不会再 fork 出孤儿会话；旧标签已关闭时会自动新建。
- 侧聊列表的显示名依次取：宿主会话标题 → 首个提问摘要 → 「侧聊 N」，并附相对时间，不再是一排相同的「侧聊」。

## 安装

本地开发（link 安装）：

```bash
dsh plugin --profile desktop add link:/absolute/path/to/dsh-sidechat
```

或从 npm 安装（发布后）：

```bash
dsh plugin --profile web add dsh-sidechat
```

安装后重启 DSH 桌面端，或对 Web 端强制刷新（Cmd/Ctrl+Shift+R）。

## 使用

1. 在主会话完成至少一轮对话（fork 需要已完成的 turn）。
2. 点顶栏「侧聊」，或选中一段文字点「在侧聊中提问」。
3. 在右侧面板继续追问；侧聊与主对话互不阻塞。
4. 需要另一条支线时打开右上「⋯」→「新侧聊」：新线程与旧线程并列，点标题可以随时切回去。
5. 回答出来后点「带回主对话」，内容会进入主输入框，可编辑后再发送。
6. 值得保留时点「在会话中打开」，侧聊即成为正式会话。

## 设计

- `lib/index.js` 只提供空宿主半包，插件是纯 UI 插件，不注册宿主路由或工具。
- `lib/client.js` 注册：
  - `sidebarRightTabs` 类型 `side-chat`（multiple + keepMounted）；
  - `sidebar.right.pane.tab` 面板体；
  - `sidebar.right.pane.tab.title` 活标题（首个提问）；
  - `conversation.session.header.utilities` 顶栏入口；
  - `conversation.chat.text-interaction` 划选入口；
  - `dshside.conversation` 子槽，内部复用 `conversation.content` / `conversation.session`。
- 列表隐藏没有宿主 API：包装 `sidebar.workspaces` 的 `useSessions` 供给，只过滤列表投影，
  store、binding 与其它消费方仍拿到全量状态；fork 期间的 `pending` 窗口避免新行先闪一下。
- 侧聊 id 写在 `dsh.sidechat.v1.hidden`；提升为会话时移除隐藏。
- 每个主会话的侧聊清单写在 `dsh.sidechat.v1.threads.<parent>`（按最近使用排序、去重），
  标签只记住“当前选中哪一条”，所以关掉再开仍然回到上次的侧聊。
- **继承历史不显示**：fork 的日志里仍有主线上下文（模型需要它），但面板通过
  `conversation.chat.node` 包装，把所有 `seq <= 分叉边界` 的消息行渲染为 null，
  只显示侧聊自己的问答；主对话没有该 Provider，渲染完全不受影响。
  分叉边界在 fork 时用**主对话当时的最后 seq** 记入线程记录，因此不依赖子会话历史
  加载时机，也不会因历史窗口只加载了一部分而漏隐藏。
- 线程身份写在 `localStorage` 的 `dsh.sidechat.v1.<parent>:<tab>`，标签恢复时复用原 child，避免重复 fork 出孤儿会话。
- 文案跟随 DSH 语言设置（`ctx.locale` 注册 zh/en 词典，宿主无 locale 服务时回退浏览器语言）。
- 不需要额外的模型循环：分叉、发送、流式、工具与审批全部走 DSH 原生 session 面。

## 已知限制

- 回流依赖主输入框挂载；主会话不在屏上时只复制到剪贴板。
- 队列与审批面板沿用原生组件，只做了字号/留白级别的紧凑化，没有专属布局。
- 模型同步只覆盖 provider/model/思考等级；其它会话级设置（如温度）不在投影面内，不被复制。
- **新建侧聊目前不自动携带主对话上下文**（从空会话起步）。下一步可加“上下文摘要注入”：把主对话最近若干轮压成一条折叠 context 行注入首个请求。
- 老版本 fork 出来的侧聊仍带继承日志，显示由边界闸门裁剪；新开的侧聊不再有该问题。
- 列表过滤依赖 `sidebar.workspaces` 槽的运行时形状；宿主改版后若包装不上，会退回原生列表（不报错、不隐藏）。

## 安装前提（重要）

DSH 桌面端运行时会锁住 profile（`~/.dsh/profiles/desktop/package.json.lock`），
必须先**退出 DSH**，再在终端执行安装命令；或在应用内的插件管理里添加
`link:/absolute/path/to/dsh-sidechat`。安装后重新启动应用。
